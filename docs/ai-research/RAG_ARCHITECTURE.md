# 4. RAG 시스템 구조 및 구현 방안

- 작성: 2026-11-19 · 구현: `ai-research/rag/` (rag.py · store_pg.py · quote_bridge.js · schema.sql) + `ai-research/docker-compose.yml`
- 목표: 손님 자동 답변이 아니라 **직원이 확인하고 쓰는 상담 도우미**

## 4.1 왜 파인튜닝보다 RAG가 먼저인가
- 가격·메뉴는 보드 메뉴판에서 자주 바뀜 → 학습시키면 옛 가격을 외움. RAG는 검색 대상만 갱신하면 됨.
- 답의 근거(과거 사례 ID)를 보여 줄 수 있음 → 직원이 검증 가능.
- 데이터 1,290대화는 학습보다는 검색에 충분한 양. 파인튜닝은 말투·형식 맞추기에만 의미(로드맵 7장).

## 4.2 구조

```
직원 질문(고객 문의 붙여넣기)
  │
  ├─① 파라미터 추출  로컬 LLM → JSON {메뉴·인분·지역}            (format=JSON 스키마)
  │        └─ 있으면 기존 견적 엔진 lib/quote-engine.js 호출 → "현재 기준 견적"  ← 숫자는 프로그램이 만듦
  ├─② 하이브리드 검색  BM25(한글 2글자 묶음) ─┐
  │                     벡터(qwen3-embedding)  ├─ RRF 결합 → 상위 3개 상담
  │                     메타(지역·인원 ±40%) ─┘
  ├─③ 답변 생성  로컬 LLM → JSON {추천 답변, 참고 사례, 참고 견적, 확인 필요, 보류, 보류 사유}
  └─④ 검증(코드)  답의 1만 원 이상 금액이 근거(엔진 결과·사례)에 없으면 / 없는 사례 ID를 대면 → 자동 보류
```

- 저장: 로컬 Docker pgvector 0.8.7(`127.0.0.1:5433`), 테이블 `consult_case`(메타 칸 + 익명화 본문 + `vector(1024)` + `tsvector`), HNSW·GIN 인덱스, 확정 견적만 모은 뷰 `confirmed_quote`.
- 같은 검색을 두 방식으로 구현: 메모리(JSON 인덱스, 개발용) / pgvector SQL 한 문장(벡터 순위 + 전문검색 순위 RRF).

## 4.3 설계 결정

| 결정 | 이유 |
|---|---|
| 상담 단위 문서 + 요약 머리말 | 견적 정보는 메시지 6~8%에만 있어 메시지 단위로 자르면 "지역·인원·금액"이 다른 조각으로 흩어짐 |
| BM25 + 벡터 + 메타 RRF | 메뉴명·지명은 키워드가 정확, "여름 야외 행사" 같은 뜻 검색은 벡터가 강함. 점수 단위가 달라 순위만 합치는 RRF가 단순·안정 |
| 한글 2글자 묶음 토큰 | 형태소 분석기 없이 "체육대회에서" ↔ "체육대회" 매칭. 패키지 추가 없음 |
| 금액은 엔진·근거에서만 | 기존 챗봇 절대 규칙과 같음. 4B 모델이 도구 없이 금액을 지어내는 것을 시험에서 확인(MODEL_EVALUATION) |
| 코드 검증으로 자동 보류 | 프롬프트 규칙만으로는 환각을 못 막음 → 모델 밖에서 숫자 대조 |
| 출력 JSON 스키마 고정 | 직원 화면에 칸별로 표시, 근거 표시를 강제 |
| `confirmed` 아닌 금액은 "확정 아님" | 협의 중 가격을 확정 견적으로 오인하지 않게 |

## 4.4 PoC 검증 결과

- 단위 테스트 11개 통과(네트워크 없이): 익명화 3, 추출 4, 전체 파이프라인 개인정보 미잔존 1, BM25·RRF 1, 키워드 검색 2
- 검색 비교(가짜 상담 12건, 질문 4개): pgvector 하이브리드 4/4 정답 1위, 메모리 하이브리드는 1건 실패 → **원인: 질문에 지역·인원이 없으면 메타 순위가 전부 0점인데 파일 순서대로 가산** → 0점 문서 제외로 수정, 회귀 테스트 추가 후 4/4
- 임베딩: 12문서 1024차원, 첫 실행 58초(모델 적재 포함)
- 근거 답변 평가(8문항): MODEL_EVALUATION.md 5.4 참고

## 4.5 운영 전환 시 바꿀 것

- 임베딩 차원 고정(모델을 바꾸면 전체 재색인) → `embed_model` 칸을 두고 모델별로 관리
- 한국어 전문검색: Postgres `simple` 사전은 띄어쓰기 단위 → `pg_bigm` 또는 앱 쪽 BM25 유지
- 권한: 직원 로그인 뒤에서만 검색, 결과에 원문 전화번호 등 없음(익명화 데이터만 적재)
- 갱신: 매일 밤 새 상담만 추가 적재(상담 ID 기준 upsert, 이미 `ON CONFLICT` 구현)
- 화면: 보드의 "챗봇 상담" 옆에 "상담 도우미" 탭 → 고객 문의 붙여넣기 → 추천 답변·근거·확인 항목 표시 → 직원이 고쳐서 보냄
