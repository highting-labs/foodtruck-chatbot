## 7.3 파인튜닝 가능성 조사 (오늘 실행 안 함)

### RAG로 해결되는 것 / 파인튜닝이 필요한 것
| 문제 | RAG | 파인튜닝 | 프로그램 로직 |
|---|---|---|---|
| 최신 가격·메뉴 | ✓(메뉴판 검색) | ✗(옛 가격을 외움) | ✓ 견적 엔진 |
| 과거 유사 사례 | ✓ | ✗ | - |
| 회사 말투·답변 형식 | △(예시 넣기) | ✓ | - |
| 도구 호출 정확도(작은 모델) | ✗ | ✓ 가장 큰 효과 기대 | △ 서버 검증 |
| 금액 환각 | △ | △ | ✓ 숫자 대조 후 보류 |

- **파인튜닝이 의미 있는 곳은 "작은 로컬 모델이 도구를 제때 부르게 하는 것"과 말투**뿐. 사실·가격은 RAG·엔진이 맡는다.

### 학습 데이터 만들기
- 원천: Claude 시험 대화 기록(`sessions/*.json`, 가짜 손님 317대화·1,433턴 — 도구 호출·결과·최종 답이 다 있음) + 익명 실제 상담의 직원 답변(승인 후)
- 형식: `{system, messages, tools}` → 정답 `assistant`(도구 호출 포함). 회귀 위반 0인 대화만 채택(Claude 출력을 정답으로 쓰는 증류 — Anthropic 이용 약관의 경쟁 모델 학습 제한 조항 확인 필요)
- 양: 도구 호출 형식 학습은 보통 수백~수천 예시가 필요. 지금 약 1,400턴 → 품질 필터 후 수백 건 예상 → **부족할 수 있음**, 고정 세트 시뮬레이터로 늘려야 함
- 품질: 금액 = 도구 결과, 접수 = 번호 받은 턴, 개인정보 없음을 자동 검사(`rescore-sessions.js` 재사용)

### LoRA / QLoRA
- 4B QLoRA: 8GB VRAM(이 PC)에서 짧은 문맥이면 가능성 있음. 단 지금 프롬프트가 약 14,000토큰이라 그대로는 메모리 부족 → 시스템 프롬프트를 줄인 학습용 형식 필요
- 9B QLoRA: 24GB급 GPU 권장 → 클라우드 GPU 시간 대여(수 시간) 또는 서버 구매 후
- 결과물은 GGUF로 변환해 Ollama에 올림

### 평가 방법
- 같은 24문항 + 고정 세트 20명 + 회귀 59대화, 지표: 도구 호출률, 근거 없는 금액 비율, 접수 누락, 응답 시간
- 학습 전후 + Sonnet 기준선을 같은 하네스(`run-eval.js`)로 비교
