# 견적 챗봇 운영 점검 절차

홈페이지 개편과 함께 챗봇을 공개한 뒤, AI가 주기적으로 실제 상담을 점검하고 문제 대화로 고친다(2026-11-23 사용자 방침).

## 주기
| 기간 | 주기 | 실행 |
|---|---|---|
| 공개 후 첫 2주 | 매일(하루 마무리 정기 작업에 붙임) | 아래 1~4 |
| 그 뒤 | 매주 월요일 | 아래 1~4, 기간 7일 |
| 늘 | 즉시 | 접수 문자 실패·손님 오류 답은 슬랙 알림(`lib/slack-alert.js`) — 점검을 기다리지 않음 |

## 1. 숫자 보기 (조회만)
- 보드 DB(Supabase 운영 프로젝트)에서 읽기 전용 쿼리 2개를 실행한다. 쓰기·수정 쿼리는 실행하지 않는다.
- `scripts/daily-sessions.sql`: 기간 안 대화 목록. 대화 id, 턴 수, 접수 여부, 오류 답, 문자 실패, 모델, 비용
- `scripts/weekly-check.sql`: 항목별 건수
  - 금액 누락
  - 번호 받고 미접수
  - 접수 문자 실패
  - 원치 않은 대표번호
  - 연락처 재요청
  - 800자 초과
- 기간은 각 파일 맨 위 `since` 한 줄만 바꾼다(매일 `1 day`, 주간 `7 days`).
- 시험 대화(sessionId가 `test-`로 시작)는 빼고 센다.

## 2. 대화 읽기
- 걸린 대화와, 접수 없이 3턴 이상 오간 대화만 원문을 읽는다. 원문은 `chat_logs`에서 그 session_id만 조회한다.
- 볼 것
  - 금액을 계산기 없이 말했는지
  - 이미 받은 정보를 다시 묻는지
  - 같은 질문을 반복하는지
  - 손님이 원하지 않은 전화 유도가 있는지
  - 손님이 화내거나 떠난 지점
  - 담당자 문자가 견적서를 쓰기에 충분한지

## 3. 분류
| 분류 | 처리 |
|---|---|
| 매뉴얼(`lib/knowledge.js`) | 고침 |
| 서버 규칙(`api/chat.js`) | 고침 |
| 계산기(`lib/quote-calc.js`·`lib/quote-engine.js`) | 고침. 금액이 바뀌면 사용자에게 먼저 확인 |
| 회사 방침 미정(할인, 계산 기준, 넘길 문의 등) | **고치지 않고 사용자에게 질문**(선택지와 추천 포함) |
| 모델 한계(같은 문제가 매뉴얼로 안 잡힘) | 운영 환경변수 `CHAT_MODEL=claude-sonnet-5-5`로 되돌릴지 사용자에게 제안 |

## 4. 고치는 순서
1. 문제 대화를 익명화(이름·번호·회사·주소를 가짜로)해서 시험장 회귀 세트에 추가한다. 실제 대화 원문은 시험장·커밋·볼트에 넣지 않는다.
2. 고친 코드로 그 대화와 회귀 세트를 재생해 확인한다(시험장 `talk.js`, 문자·시트·DB 막힘).
3. dev로 PR을 올린다. 급한 문제(접수 누락·금액 오류·오류 답)는 그날 운영 반영을 요청하고, 사소한 건 모아 주 1회 반영한다.

## 결과 남기기
- 그날 볼트 기록(`foodtruck-quote`)에 한 줄을 남긴다: 대화 n·접수 n·문제 n(분류별)·조치(PR 번호).
- 사용자 결정이 필요한 것은 "앞으로 할 일"에 넣는다.
- 손님 이름·번호·회사·주소·대화 원문은 기록하지 않는다. 대화 id와 요약만 남긴다.

## 비용
- 조회·요약은 하루 몇십 원 수준이다.
- 회귀 재생은 고칠 때만 한다(1~3달러).
